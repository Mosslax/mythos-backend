# Mythos核心：SDK与运行时

Mythos 是一个多媒体处理程序。它将不同功能封装为任务节点，通过组装任务节点得到工作流。Mythos 通用 SDK 模块主要包含数据抽象和接口定义。

## 1. 文件资源抽象

Mythos 中各种功能都是对数据的操作。Mythos将一切数据都抽象为文件资源类 `File` ，以 refer 形式记录其存取方式。其优势在于：

* [1] 将文件和文件的存取方式进行解耦。
* [2] 适合在本地线程/进程间以及本地和远程服务之间传输。

相关代码位于 `net.s1lentm4ple.mythos.common.file` 下。

### 1.1. 表层抽象

Mythos 中文件资源的表层抽象，目标是在默认路径上对业务隐藏"获得二进制流"的细节，同时保留显式查看 refer 的能力。`File` 内部只保存纯数据：内容标识 `contentId`、声明元数据 `declaredMetadata` 和观测元数据 `observerdMetadata` ，以及跨进程传输时的 refer 快照。refer 表与解析组件由框架管理。

* [1] **数据对象**：
    * [1.1] **纯数据类**： `File` 是纯数据类，其构造不依赖任何服务或解析组件。
    * [1.2] **可序列化**： `File` 能被序列化以便在本地线程/进程间及本地与远程服务之间传输；序列化内容包含 `contentId` 及该标识下的 refer 快照。观测元数据是读取后的进程内派生物，不参与传输。
    * [1.3] **Refer 由框架托管**：`File` 不负责 refer 的增删与一致性维护，refer 由框架以 `contentId` 为索引统一登记和管理。多 refer 之间不做强一致保证：框架在登记时做廉价校验，接收方在读取时校验实际内容。
    * [1.4] **元数据分层**：声明元数据由构造方声明；观测元数据在 `getContent()` 完成读取后由框架写入，只记录与解析路径无关的实测事实。
* [2] **文件存取机制**：
    * [2.1] **无参数实例方法**：调用方以 `file.getContent()` 获取二进制流,以 `file.getRefers()` 获取 refer 快照，不使用 `loader.load(file)` 的外部加载模式。主语是数据对象本身，而非加载器。
    * [2.2] **调用方默认无感知**：调用方可以不感知解析路径；框架默认隐藏细节，同时提供显式接口供调用方查看或选择 refer 。当读取完成并通过校验时，调用方可以认为内容与声明的 `contentId` 一致，与具体走哪条解析路径无关。
    * [2.3] **委托外部组件获取二进制流**： `getContent()` 的实现中不包含具体的解析逻辑，仅负责将请求分派到外部可替换的解析组件。

文件refer的数据类 `Refer` 也是纯数据类，目前只包含refer类型和路径两个属性。
